# TPKE (Threshold Public Key Encryption)

一个基于 BLS12-381 椭圆曲线的 TPKE 实现。

## ChatGPT 给出的解释

Threshold Public Key Encryption（阈值公钥加密）是一种把“解密权力”分散到多个参与者手中的公钥加密体制。

核心思想是：
公钥是公开且唯一的，但对应的私钥不会由任何单一实体完整持有，而是被分割成 n 份私钥份额，分别由 n 个参与者持有。系统设定一个阈值 t，只有当至少 t 个参与者协作时，才能完成解密；少于 t 个时，无法获得任何关于明文的有效信息。

基本结构如下。
1）密钥生成（Distributed Key Generation, DKG）：
参与者通过分布式协议共同生成公钥 PK，并各自获得一个私钥份额 SK_i。过程中不需要可信中心，也不会出现“完整私钥”。

2）加密（Encryption）：
任何人使用公钥 PK 对消息 m 进行加密，得到密文 C。这一步与普通公钥加密没有本质区别。

3）部分解密（Partial Decryption）：
当需要解密时，至少 t 个参与者各自用自己的私钥份额对密文 C 计算一个“部分解密”结果 D_i。

4）合并（Combine）：
将 t 个有效的部分解密结果通过插值或聚合算法合并，恢复出明文 m（或等价的完整解密结果）。

安全性质。

* 阈值安全性：任意少于 t 个私钥份额在信息论或计算意义上不泄露私钥或明文。
* 鲁棒性：即使部分参与者掉线或作恶，只要仍有至少 t 个诚实参与者，系统就能正确解密。
* 去中心化：不存在单点私钥泄露风险。

常见构造。

* 基于 ElGamal 的阈值加密（最常见）：利用指数运算的可分解性，部分解密是对密文分量做幂运算。
* 基于 Paillier 的阈值加密：支持同态加法，常用于投票、隐私计算。
* 基于 pairing 的方案：常与 BLS、IBE、去中心化密钥管理结合。

典型应用场景。

* 去中心化密钥管理（如区块链、分布式系统中的 master key）。
* 阈值解密的投票系统：只有在满足法定人数后才能公开结果。
* 共识与BFT协议中延迟解密（如 HoneyBadgerBFT 中的阈值加密/解密）。
* 需要抗内部攻击的高安全加密服务。
